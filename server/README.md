# Lokaler Inferenz-Server

Zwei Teile:

1. **`laya-serve`** (Docker, Port `11500`) — bildet TypeSafes Jev-Wire-API lokal nach.
   Wird von der Extension nicht mehr direkt angesprochen, sondern nur noch als Upstream
   für die Laya-Backends im Shim genutzt.
2. **`shim_server.py`** (Port `8787`) — der Endpunkt, den die Extension tatsächlich anspricht.
   Spricht dasselbe `/v1/systemone`-Format, routet aber je nach `model`-Feld zu Laya
   (Proxy zu 1.) oder zu **TMR** (`Oxidane/tmr-ai-text-detector`, lokal geladen, kein
   Laya/Jev-Bezug — ein eigenständiger, bereits trainierter Klassifikator).

Warum der Umweg: Laya hat laut eigener Doku und unserem eigenen Test (siehe unten und
`../training/EVAL_RESULTS.md`) **keine brauchbare Zero-Shot-Erkennung** für "ist das
KI-generiert" (AUROC 0.549 auf unserem 100er-Testset, faktisch Münzwurf). TMR ist dafür
tatsächlich trainiert (AUROC 0.911) und braucht kein eigenes Fine-Tuning. Der Shim hält
beide Optionen hinter demselben Wire-Format, damit man in den Extension-Optionen einfach
zwischen den Backends umschalten kann, ohne Extension-Code anzufassen.

## 1. `laya-serve` starten (Docker)

```
.\run_server.ps1
```

Startet den Container auf `127.0.0.1:11500` (nicht öffentlich erreichbar), lädt Checkpoint
`english`. Nur nötig, wenn man in der Extension ein Laya-Backend (`english`/`multilingual`)
ausprobieren will — für den empfohlenen Default (`tmr`) NICHT erforderlich.

Manuell (falls das Skript nicht passt):

```powershell
docker run -d --name laya -p 127.0.0.1:11500:11500 -e LAYA_MODELS=english ghcr.io/ouijan/laya-serve
```

Ohne Docker (aus deren README, `uv`):

```bash
git clone https://github.com/ouijan/laya-serve
cd laya-serve
uv venv --python 3.13
uv pip install -e .
LAYA_PORT=11500 laya-serve --cpu
```

**Korrektur (verifiziert 2026-09-23, nicht nur aus Doku übernommen):** Der echte
Health-Endpoint heißt **`/health`**, nicht `/healthz` wie ursprünglich recherchiert
(404 bestätigt per `GET /openapi.json` — tatsächliche Routen sind `/health`,
`/v1/systemone`, `/v1/route`; `/v1/models` existiert entgegen erster Recherche NICHT).

```powershell
Invoke-RestMethod http://127.0.0.1:11500/health
```

## 2. `shim_server.py` starten

```powershell
cd server
uv venv .venv --python 3.12
uv pip install --python .venv -r requirements_shim.txt
.venv/Scripts/python.exe shim_server.py
```

Läuft auf `127.0.0.1:8787`. Lädt TMR automatisch beim ersten `model: "tmr"`-Request
(ein paar Sekunden), Laya-Requests werden nur durchgereicht — dafür muss `laya-serve`
(Schritt 1) separat laufen.

```powershell
Invoke-RestMethod http://127.0.0.1:8787/healthz
# {"ok": true, "laya_upstream": true/false, "tmr_loaded": true/false}
```

## Beispiel-Request (verifiziert)

```powershell
$body = @{
  model     = "tmr"
  state     = @{ candidates = @(@{ text = "Maintaining a bicycle in good working condition requires regular attention." }) }
  questions = @{ c0 = @{ type = "noul"; instructions = "Is candidates[0].text primarily generated by an AI/LLM?" } }
} | ConvertTo-Json -Depth 6

Invoke-RestMethod -Uri http://127.0.0.1:8787/v1/systemone -Method Post -ContentType "application/json" -Body $body
```

`model: "english"` / `"multilingual"` im selben Request schickt stattdessen an `laya-serve`
weiter (muss dafür laufen) — identisches Antwortformat, Extension merkt keinen Unterschied.

## Verifizierte Befunde (2026-09-23)

- **Laya zero-shot ist unbrauchbar:** Accuracy@0.5 = 0.510, AUROC = 0.549 auf 100
  balancierten HC3-Beispielen — praktisch Münzwurf, durch keine Schwelle behebbar.
- **TMR trennt gut, braucht aber eine hohe Schwelle:** AUROC 0.911, aber bei Schwelle 0.5
  wurden 45 von 50 menschlichen (informellen Reddit-Style-)Texten fälschlich als KI markiert
  (Score-Mittelwert insgesamt 0.893 — Modell tendiert auf dieser Domäne generell zu hohen
  Scores). Mit Schwelle 0.98 (auf diesem Sample optimiert): Accuracy 0.830.
  → Extension-Default dementsprechend auf Schwelle **0.90**, nicht 0.70, gesetzt.
  Details/Reproduktion: `../training/EVAL_RESULTS.md`.
- Batch-Format (`state.candidates[]` + `noul`-Frage pro Index) funktioniert identisch für
  beide Backends über den Shim.

## Stoppen

```powershell
docker stop laya; docker rm laya
# shim_server.py: Strg+C im laufenden Terminal
```
